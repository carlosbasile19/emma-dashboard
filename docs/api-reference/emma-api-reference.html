Section 01

Architecture at a glance

Emma is a read-only, multi-tenant analytics dashboard. Three layers, one rule: the browser never holds a key, and every data fetch is scoped to a client_id derived from the signed-in session — never from the browser.

1.1Isolation guarantees

  • One key, one agency. The dashboard holds a single agency-scoped API key. The key is the agency — no agency_id is ever passed; a foreign client_id returns 404 client_not_found, never data.
  • Session-derived tenant. getSessionClientId() (lib/auth.ts) is the single source of tenant identity. Members are locked to exactly one client; the emma-active-client switching cookie is honored only for platform admins, and only after validation against the agency’s own client set.
  • Server-only key. All upstream modules are server-only. The SSE and recording proxies exist precisely so the browser can consume cross-origin streams without ever seeing the key.
  • Tenant-namespaced cache. Every cache key includes client_id — isolation by construction, not just an optimization.
Section 02

Authentication & scopes

Two independent auth systems: an agency API key (server-to-server, upstream) and Supabase user sessions (browser, dashboard). Scopes gate the key; roles gate the user.

2.1The agency API key

Every upstream request sends the key in a header. It is minted by an upstream operator (Settings → API Keys) and lives only in the OLIVIA_API_KEY env var on Emma’s backend.

# every server-to-server request
x-api-key: oa_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

2.2Key scopes

ScopeGrantsWithout it
clients:read Discovering the agency’s clients (§4.1) — the client_ids every other call needs. 403 forbidden_scope
dashboard:read All per-client analytics endpoints (§4.2–4.4): overview, timeseries, outcomes, funnel, agents, campaigns, pipelines, calendar, leads, calls, conversations, DM threads, costs. 403 forbidden_scope
dashboard:pii Un-redacts PII on list & drill-down endpoints: names, phones, emails, Instagram handles, recording URLs, transcripts, conversation summaries and DM message bodies. Fields are omitted entirely; conversation threads return locked: true with empty messages.
dashboard:notes The one analytics write: PUT …/leads/{leadId}/notes (≤ 20,000 chars). Notes render read-only in the lead page.
dashboard:brief The briefing bridge (§5.1) — starting, polling and ending live voice briefings. “Brief Emma” degrades to a local simulated preview.
dashboard:report The reporting bridge (§5.2) — voice reporting walkthrough sessions (+ SSE transcript). Add dashboard:pii for Emma to speak lead names. “Reporting walkthrough” degrades to a local simulated preview.
Activation state. The voice bridges are additionally flag-gated in Emma (OLIVIA_BRIEFING_ENABLED / OLIVIA_REPORTING_ENABLED). Going live requires both the flag and the corresponding scope on the production key — the scope grants are the outstanding step at the time of writing.

2.3Dashboard user auth (Supabase)

Sign-in flow
  • Passwordless magic link (sendMagicLink, never auto-creates users) with a password fallback.
  • Emails are branded & delivered via Resend through the signed /api/auth/email-hook webhook.
  • The link lands on /auth/callback, which exchanges the code (PKCE or token_hash) for a session and redirects to /dashboard.
  • middleware.ts refreshes the session on every page navigation and bounces unauthenticated visitors to /login. Public paths: /, /login, /auth, /invite.
Roles
  • member  Locked to exactly one client workspace via workspace_members. The client-switch cookie is ignored entirely.
  • platform_admin  May switch across all agency clients (validated cookie) and holds the /console agency-admin app: invites, team, roster sync, costs.
  • requireAdmin() gates every console page, console action and every lib/olivia/agency.ts export — 403 for members.
  • Invited users join via single-use, 7-day tokens (acceptInvite) — the token is the credential; conflicting mappings are refused, never silently re-mapped.

3.3Envelopes & errors

Detail/aggregate endpoints return an object directly. List endpoints return { "<resource>": […], "total": N, "page": P, "limit": L }. Errors always share one envelope:

{ "error": "Client not found", "code": "client_not_found" }
StatuscodeMeaning
401unauthorizedmissing / invalid / revoked / expired key.
403forbidden_scopekey lacks the required scope (§2.2).
404client_not_found · lead_not_found · conversation_not_found · agency_not_found · reporting_not_foundid doesn’t exist or isn’t in this agency — foreign ids are indistinguishable from missing ones.
400invalid_request · invalid_date_range · invalid_timezone · date_range_too_largebad from/to/tz or body.
429rate_limited · reporting_concurrency_limitback off using the Retry-After header.
500internal_errorserver error — safe to retry with backoff.

In Emma’s code these become a typed OliviaError { status, code, message, retryAfterSeconds? } (lib/olivia/errors.ts).

3.4Rate limits & PII redaction

Rate limits
  • Upstream: 120 req/min per IP, 600 req/min per key, shared bucket across analytics.
  • Emma self-throttles below that: a cross-instance token bucket (~500/min via the consume_rate_token RPC), single-flight locks per cache key, and stale-while-revalidate caching (§7.3), so bursts of dashboard traffic never hit upstream 1:1.
  • oliviaFetch retries 429s up to 2× honoring Retry-After (capped 30s + jitter). Voice-bridge starts use maxRetries: 0 so concurrency 429s surface instantly.
PII (very important)
  • List & drill-down endpoints omit PII fields entirely unless the key carries dashboard:pii — build for the redacted shape by default.
  • Never returned under any scope: raw provider cost, per-lead/per-call cost, internal notes-intelligence, custom fields, CRM ids, provider call ids.
  • Spend figures are billed amounts (what the agency is charged), basis billed_voice, integer cents.

Section 05

Voice bridges

The two places the API is not a plain GET: starting an ephemeral voice session where Emma narrates a client’s numbers over a browser call (Retell web call). Actions never mutate leads, calls or analytics.
Session lifecycle queued→ connecting→ live→ ended / failed

5.1Briefing bridge dashboard:brief

“Brief Emma” on the Overview: Emma voice-narrates the catch-up agenda (bookings to confirm → new leads to work → leads to chase → conversions → campaign results) for a window and focus.

POST /clients/{clientId}/briefings
Start a briefing. Returns the prioritized agenda plus short-lived Retell web-call credentials, bound to this briefing_id + client_id. With voice: false, returns the agenda only. Concurrency-capped (≤ 3 live per key) → 429 + Retry-After.
Body
{ from?, to?, tz?, focus?: "all"|"bookings"|"leads"|"campaigns", voice?: bool }
{
  "briefing_id": "brf_8f3b…", "client_id": "8f3b…", "status": "connecting",
  "agenda": [ { "id": "bookings", "category": "bookings",
                "title": "12 appointments to confirm", "priority": 1 }, … ],
  "realtime": { "provider": "retell", "access_token": "eyJ…", "call_id": "call_abc123", "expires_at": "…" }
}
GET /clients/{clientId}/briefings/{briefingId}
Status + running transcript, with current_item_id tracking which agenda item Emma is speaking (drives the “Speaking now” highlight; poll ~2s).
POST /clients/{clientId}/briefings/{briefingId}/end
Ends the briefing and tears down the voice session → { "status": "ended" }.

5.2Reporting bridge dashboard:report

“Reporting walkthrough” next to Brief Emma: headline metrics, today’s call schedule and outstanding looms, with optional voice drill-down into one agent. Strictly single-client; cross-client comparison is disabled server-side. Optional dashboard:pii lets Emma speak lead names.

MethodPath (under …/clients/{clientId})Purpose
POST/reportingStart a session. Body { from?, to?, tz?, agent_id? } → 201 { reporting_id, status, period, summary { schedule_count, loom_count }, realtime }. Join Retell within ~60s. Limit 3 concurrent/agency → 429 reporting_concurrency_limit + Retry-After: 30.
GET/reporting/{id}Status + transcript (polling fallback ~2s): { status, started_at, ended_at, transcript[] { role, text, at } }.
GET/reporting/{id}/streamSSE (preferred): named events status / transcript / ended. Closes on terminal status or ~110s.
POST/reporting/{id}/endIdempotent end → { "status": "ended" }. Called on hang-up / unmount.
Activation. Both bridges are flag-gated in Emma: OLIVIA_BRIEFING_ENABLED / OLIVIA_REPORTING_ENABLED. Until the flag is on and the key carries the scope, the modals run a local simulated preview — same UI, no live call. The browser only ever receives the short-lived realtime join token, never the agency key.
Section 06

Dashboard HTTP endpoints

Emma’s own Next.js route handlers — same-origin endpoints the browser (or Supabase / Vercel cron) calls. Each one self-authenticates; middleware deliberately excludes /api/*.
GET /api/reporting/{id} Supabase session
Reporting-status proxy (polling fallback). The client_id is resolved from the session server-side, so a user can only read their own workspace’s session. Cache-Control: private, no-store; upstream errors pass through (or 502) with Retry-After preserved.
GET /api/reporting/{id}/stream Supabase session
Same-origin SSE proxy for the live reporting transcript. Opens the upstream stream server-side (browser EventSource can’t send the key) and pipes status / transcript / ended events verbatim. Browser abort flows through request.signal to tear down upstream. maxDuration: 120s.
GET /api/calls/{id}/recording?src=… Supabase session
Call-recording download proxy (recordings are cross-origin without CORS). SSRF-guarded: src must be https and host-allowlisted (RECORDING_HOST_ALLOWLIST, default = the voice provider’s CDN). Streams as attachment; filename="call-<id>.mp3". Errors: 400 bad_src, 502 upstream_*.
POST /api/auth/email-hook webhook signature
Supabase “Send Email” auth hook. Verified with Standard Webhooks signatures (SEND_EMAIL_HOOK_SECRET); invalid signature → 401. Renders the branded magic-link template and sends via Resend; notification-only payloads (no token_hash) are acknowledged without sending.
GET /api/cron/snapshot cron bearer secret
Daily snapshot entrypoint (Vercel cron 5 0 * * *). Disabled by default (SNAPSHOTS_ENABLED); when enabled it is fail-closed — CRON_SECRET must be set (500 if not) and the request must carry Authorization: Bearer <CRON_SECRET> (401 otherwise). Runs runDailySnapshots() across all mirrored clients.
GET /auth/callback magic-link token
Magic-link landing: exchanges ?code (PKCE) or ?token_hash&type for a Supabase session, then 302 to next (default /dashboard); failures bounce to /login?error=link.

7.3Cache & governor — lib/olivia/cache.ts, governor.ts

Stale-while-revalidate
  • Backed by the Supabase response_cache table; per-endpoint freshness tiers (overview 60s/300s … threads 15s/60s … discovery 1h/24h).
  • Serves fresh → stale → last-known-good, refreshing in the background; single-flight lock prevents thundering herds.
  • Cache keys always embed client_id — tenant isolation by construction.
Cross-instance rate governor
  • Postgres RPCs: consume_rate_token (token bucket ~500/min, under the upstream 600/min), try_acquire_lock, release_lock.
  • Fail-open on infra errors; over budget with no cache → typed 429 rate_limited to the UI.

8.1Metric definitions (don’t guess — exact semantics)

MetricDefinition
bookings_rateThe “conversion” KPI: distinct in-window leads with a non-cancelled booking or status = 'booked' ÷ total in-window leads. Excludes the manual won-deal converted status.
converted_countLeads in the converted stage (manual “won deal”) — deliberately shown separately from bookings.
calls_totalDistinct leads with a real conversation (completed call > 10s, or in progress) — not raw call rows. Raw per-day counts live in /timeseries and /outcomes.
pickup_rateOutbound only, lead-level: leads that ever picked up ÷ leads attempted (inbound excluded).

9.1Security checklist

  • The agency key lives in a backend secret store and never reaches the browser — all upstream calls are server-side; anything the frontend needs is proxied same-origin.
  • Request dashboard:pii only where the product genuinely needs names/contacts/transcripts; the UI is built for the redacted shape by default.
  • Every client_id comes from the session. A wrong or foreign id returns 404 client_not_found — never data.
  • Handle 401 (key rotated/revoked), 403 (missing scope), 429 (back off with Retry-After), 400 (fix params) — all typed as OliviaError.
  • Voice-bridge tokens are short-lived, single-session, and bound to one briefing_id/reporting_id + client_id; ending a session tears down the call.
  • Webhooks and crons authenticate independently: Standard Webhooks signatures for the email hook, a fail-closed bearer secret for the snapshot cron, an SSRF host-allowlist for the recording proxy.
